# Repository Guidelines

## Project Structure & Module Organization

This is a TanStack Start + Vite + React 19 TypeScript app.

- `src/routes/`: file-based route definitions (`__root.tsx`, `index.tsx`, etc.).
- `src/components/`: reusable UI, with primitives in `src/components/ui/`.
- `src/lib/`: shared helpers and integrations.
- `src/content/`: typed static content organized by domain.
- `src/assets/images/`: build-managed image assets imported by content modules.
- `src/styles/`: global styling (`app.css`) with Tailwind v4 and shadcn tokens.
- `public/`: static files served directly without Vite processing.
- Static hosting output: `dist/client` (generated).

Do not hand-edit `src/routeTree.gen.ts`; it is generated by TanStack tooling.

## Build, Test, and Development Commands

- `bun install`: install dependencies from `bun.lock`.
- `bun run dev`: start local dev server (Vite, port `3000`).
- `bun run build`: produce production build (`dist/client` and server bundle).
- `bun run start`: serve the production static output locally on port `4173`.
- `bun run lint`: check formatting and lint rules.
- `bun run lint:fix`: auto-fix formatting and lint issues.
- `bun run typecheck`: run TypeScript without emitting files.
- `bun run check:output`: validate the generated static deployment artifact.
- `bun run test:smoke`: run the desktop/mobile nonvisual Playwright smoke suite against `dist/client`.
- `bun run test:playwright`: run all desktop/mobile Playwright interaction and visual tests against `dist/client`.
- `bun run check`: run lint, type checks, build/output assertions, and the full Playwright suite.

## Coding Style & Naming Conventions

Formatting and linting are enforced via Biome (`biome.json`):

- Tab indentation, semicolons, trailing commas, double quotes (Biome defaults).
- Biome supports JS/TS/JSX/TSX, JSON, and CSS. It does not format HTML, Markdown, or YAML.

Code conventions:

- Use TypeScript for app code (`.ts`/`.tsx`).
- Components and modal/view files use `PascalCase` (for example `ImageModal.tsx`).
- Utility modules use lower-case names (for example `utils.ts`).
- Keep route filenames aligned with URL structure under `src/routes/`.

## Testing Guidelines

- Validate static output with `bun run check`, which includes the Chromium Playwright suite at desktop and mobile viewports.
- Smoke tests live in `tests/smoke.spec.ts` and run against the production `dist/client` output, not the Vite development server.
- For UI changes, keep coverage for key routes (`/`, `/areyou`), 404 handling, images, and modal/gallery interactions.

## Commit & Pull Request Guidelines

Recent history favors short, imperative commits with optional prefixes:

- Examples: `feat: ...`, `fix: ...`, `chore: ...`.

For pull requests:

- Include a concise summary of user-visible changes.
- Link related issues when applicable.
- Add before/after screenshots for UI work.
- Note any deployment-impacting changes to Amplify infrastructure, GitHub Actions, Vite plugins, or environment usage.
