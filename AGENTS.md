# Repository Guidelines

## Project Structure & Module Organization
This is a TanStack Start + Vite + React 19 TypeScript app.
- `src/routes/`: file-based route definitions (`__root.tsx`, `index.tsx`, etc.).
- `src/components/`: reusable UI, with primitives in `src/components/ui/`.
- `src/lib/`: shared helpers and integrations (for example `contentful.ts`).
- `src/data/`: static content (`site-data.json`).
- `src/styles/`: global styling (`app.css`) with Tailwind v4 and shadcn tokens.
- `public/`: static files served directly (mostly image assets).
- Build output: `dist/client`; server output: `.output/server` (generated).

Do not hand-edit `src/routeTree.gen.ts`; it is generated by TanStack tooling.

## Build, Test, and Development Commands
- `bun install`: install dependencies from `bun.lock`.
- `bun run dev`: start local dev server (Vite, port `3000`).
- `bun run build`: produce production build (`dist/client` and server bundle).
- `bun run start`: run the built server from `.output/server/index.mjs`.

## Coding Style & Naming Conventions
Formatting is enforced via Prettier (`.prettierrc`):
- 2-space indentation, semicolons, trailing commas, single quotes.
- `printWidth: 140`.

Code conventions:
- Use TypeScript for app code (`.ts`/`.tsx`).
- Components and modal/view files use `PascalCase` (for example `ImageModal.tsx`).
- Utility modules use lower-case names (for example `utils.ts`, `contentful.ts`).
- Keep route filenames aligned with URL structure under `src/routes/`.

## Testing Guidelines
There is currently no committed automated test suite or `test` script.
- For now, validate changes with `bun run dev` and a production check via `bun run build`.
- For UI changes, verify key routes (`/`, `/areyou`) and modal/gallery interactions.
- If adding tests, prefer colocated `*.test.ts(x)` files and document new commands in `package.json`.

## Commit & Pull Request Guidelines
Recent history favors short, imperative commits with optional prefixes:
- Examples: `feat: ...`, `fix: ...`, `chore: ...`.

For pull requests:
- Include a concise summary of user-visible changes.
- Link related issues when applicable.
- Add before/after screenshots for UI work.
- Note any deployment-impacting config changes (`netlify.toml`, Vite plugins, env usage).
